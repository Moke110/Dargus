# D-Base Storage & Lifecycle

> D-Base separates authoritative append-only data from derived views so the store remains auditable, rebuildable, and safe to re-ingest.

## Directory layout

```
~/.dargus/dbase/
├── data/shard-{writer_id}.jsonl            # authoritative evidence (50-field records)
├── views/dbase.parquet                     # derived queryable view
├── sidecars/status.jsonl                   # evidence_id → {status, superseded_by?} lifecycle sidecar
├── sidecars/llm_summary.jsonl              # evidence_id → LLM summary sidecar
├── sidecars/embeddings-{model_fp}.jsonl    # evidence_id → vector for a specific embedding model
├── sidecars/embeddings_manifest.json       # active model fingerprint + available model fingerprints
├── manifest.json                           # schema version + shard inventory
├── field_registry.yaml                     # stable_key → logical path mapping
└── vocabularies.json                       # controlled vocabularies
```

## File roles

- `data/shard-*.jsonl` — append-only authoritative records. Once written, a shard line is never modified or removed.
- `views/dbase.parquet` — rebuildable analytical view.
- `sidecars/status.jsonl` — append-only lifecycle sidecar. Each entry carries `evidence_id`, `status`, and optionally `superseded_by`. The latest entry for an `evidence_id` wins; a record with no entry is `active`.
- `sidecars/llm_summary.jsonl` — append-only LLM summaries keyed by `evidence_id`.
- `sidecars/embeddings-*.jsonl` — append-only embedding vectors keyed by `evidence_id` and model fingerprint.
- `sidecars/embeddings_manifest.json` — tracks which model fingerprint is active and which fingerprints have been generated.
- `manifest.json` — store metadata.
- `field_registry.yaml` and `vocabularies.json` — schema authority.

## Sidecar fields

Three fields live outside the evidence record, each in its own append-only sidecar file keyed by `evidence_id`: `status` (with `superseded_by`), the LLM summary, and the embedding. None of them participates in the `evidence_id` identity hash, so sidecar updates never change evidence identity. Records are immutable; all lifecycle and derived state changes are new sidecar entries.

## Write lifecycle

1. Validate against the 50-field schema.
2. Compute `evidence_id` from identity fields.
3. Exact dedup: skip if `evidence_id` exists.
4. Semantic dedup: flag near-duplicates for review.
5. Generate an embedding via the embedding tool and append it to `sidecars/embeddings-{active_model_fp}.jsonl` keyed by `evidence_id`.
6. Append the record to the current JSONL shard under file lock.
7. Mark the Parquet view stale.

## Re-embedding

When the project's embedding model changes (via `dargus config`), D-Base runs a re-embedding pass:

1. Compute the new model fingerprint.
2. For every active `evidence_id`, generate a new vector with the new model.
3. Append the new vectors to `sidecars/embeddings-{new_fp}.jsonl`.
4. Update `sidecars/embeddings_manifest.json` to mark the new fingerprint active.

The old embedding file is kept, so switching back does not require recomputation. Re-embedding is idempotent: re-running it with the same model fingerprint skips already-generated vectors.

## Status lifecycle

| Status | Meaning |
|---|---|
| `active` | Default; visible to Predict |
| `superseded` | Replaced; hidden from Predict |
| `retracted` | Invalid; ignored by Predict |
| `holdout-test` | Temporarily reserved for Benchmark |
| `holdout-valid` | Temporarily reserved for validation |

Status changes are lifecycle transitions, not record edits. Every transition — `superseded`, `retracted`, `holdout-test`, `holdout-valid`, or back to `active` — appends a new entry to `sidecars/status.jsonl`. Corrections are new records, and the old record is superseded by appending a `{evidence_id, status: superseded, superseded_by}` entry. Retraction appends a `{evidence_id, status: retracted}` entry; no replacement record is required.

Benchmark flips matching `active` records to `holdout-test`, runs Predict on remaining `active` records, and restores status afterward — each flip is a status sidecar entry. No temporary D-Base is created.

## Recovery

The JSONL shards are authoritative. The Parquet view can always be rebuilt from them. If embedding generation is unavailable, the evidence record is still written; semantic search simply skips records that have no vector for the active model fingerprint. Re-embedding can fill the gap later.

## v1.0.0 scope

- Append-only JSONL shards with file-lock safety.
- Rebuildable Parquet view.
- Three append-only sidecar tables (status, LLM summary, embeddings) keyed by `evidence_id`; embedding sidecars also keyed by model fingerprint.
- Status lifecycle (supersede, retract, holdout) via sidecar entries; records are never mutated.
- Re-embedding support when the project changes its embedding model.
- Exact + semantic deduplication.
- Status management supporting Benchmark holdout semantics.
