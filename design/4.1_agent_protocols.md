# Agent Protocols

> Agents in Dargus communicate through typed data classes. The protocols make every prediction inspectable: you can see what each Expert concluded, what evidence it used, and why the final DCS has the value it does.

## AgentReport

Every `BaseAgent.run()` returns an `AgentReport`:

```
agent_name      str
rounds          int
converged       bool
confidence      float
findings        list
call_trace      list[CallTrace]
data_gaps       list[str]
bias_notes      list[str]
```

## CallTrace

`CallTrace` records what happened during one phase of one round:

```
round           int
phase           str   # perceive | reason | act
tool_called     str | None
skill_used      str | None
knowledge_retrieved list[str]
output_summary  str
elapsed_ms      int
error           str | None
```

## ExpertReport

An `ExpertReport` captures one Expert’s assessment of a set of evidence records for a specific drug-disease-endpoint context. It contains the Expert’s findings, confidence, delegations, data gaps, and bias notes.

## EvidenceAssessment

Within an `ExpertReport`, each assessed record is represented by an `EvidenceAssessment` that records relevance, quality score, and limitations.

## TaskDelegation

When an Expert decides another Expert is better suited to evaluate some records, it emits a `TaskDelegation` containing the target Expert and the evidence IDs to hand off.

## FinalReport

`D4Expert.conclude()` produces a `FinalReport` by synthesizing all Expert reports. It includes:

- `efficacy_score` (DES, 0–1 scale) and `confidence_score` (DCS, 0–1 scale), reported together as **DES ± DCS** — or unset when confidence is `insufficient_data`,
- `supporting_records` — the evidence IDs that justify the prediction,
- `confidence_level` — a qualitative confidence label,
- `expert_consensus` — where Experts agree,
- `contradictions` — where they disagree,
- `data_gaps` — what evidence is missing.

## Universal prediction contract

All predictions in Dargus return the same nested structure:

```json
{
  "drug_id": {
    "disease_id": {
      "endpoint": {
        "efficacy_score": 0.5,
        "confidence_score": 0.5,
        "supporting_records": ["ev_..."],
        "reasoning_mode": "Iris-expert",
        "confidence_level": "moderate"
      }
    }
  }
}
```

## Score-based uncertainty

`efficacy_score` and `confidence_score` are not post-processed margins. They must be derived from the model’s own assessment of evidence uncertainty. A high DCS (wide DES ± DCS range) is an honest output when evidence is weak or contradictory.

## Supporting records requirement

Every prediction must cite at least one supporting evidence ID from D-Base. Exception: a report with `confidence_level: insufficient_data` (scores unset) may cite zero supporting records. The `ReportValidationHook` rejects any final report that violates this rule.

## v1.0.0 scope

- `AgentReport`, `CallTrace`, `ExpertReport`, `EvidenceAssessment`, `TaskDelegation`, `FinalReport`.
- Universal nested prediction contract with DES ± DCS.
- Supporting-record traceability enforced by `ReportValidationHook`.
